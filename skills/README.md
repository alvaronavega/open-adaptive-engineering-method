# Skills Directory

## Purpose

This directory is reserved for OAEM-aligned engineering Skills that operationalize methodology behaviors.

Skills support OAEM, but they do not define OAEM core principles by themselves.

## What belongs here

- reusable, composable workflow Skills aligned with OAEM contracts;
- Skills for classification, slicing, verification, checkpointing, and review;
- Skill documentation that references OAEM method contracts and boundaries.

## What does not belong here

- project-specific private prompts mixed as canonical OAEM assets;
- harness-specific runtime internals (these belong in adapters);
- copied third-party skill packs without explicit governance fit.

## v0.1 maturity

No full production OAEM Skill implementations are shipped in foundation v0.1.

At this stage, OAEM documents the role of Skills and the expected direction.

## Early skill roadmap direction (conceptual)

Initial OAEM Skills are expected to include concepts such as:
- `assess-project`
- `adopt-oaem`
- `reorganize-existing-project`
- `audit-documentation`
- `classify-change`
- `grill-requirement`
- `slice-vertically`
- `create-temporary-spec`
- `implement-slice`
- `diagnose-defect`
- `verify-evidence`
- `checkpoint-work`
- `verify-completion`
- `review-change`
- `retrospective`

### Particularly important for existing repositories

- `adopt-oaem`: incrementally introduce OAEM in an existing project.
- `reorganize-existing-project`: classify source/generated/research/history/vendor content and simplify safely.
- `audit-documentation`: detect authority overlap, stale documents, duplication, and contradiction.

These are roadmap concepts only in v0.1 foundation.
