# Skills Directory

## Purpose

This directory is reserved for OAEM-aligned engineering Skills that operationalize methodology behaviors.

Skills support OAEM, but they do not define OAEM core principles by themselves.

## What belongs here

- reusable, composable workflow Skills aligned with OAEM contracts;
- Skills for classification, slicing, verification, checkpointing, and review;
- Skill documentation that references OAEM method contracts and boundaries.

## What does not belong here

- project-specific private prompts mixed as canonical OAEM assets;
- harness-specific runtime internals (these belong in adapters);
- copied third-party skill packs without explicit governance fit.

## v0.1 maturity

OAEM now includes initial core and adoption-oriented Skill contracts for practical use in existing projects.

Current available Skills include:

- `grill-requirement` — progressive requirement discovery to reach decision-ready clarity. Trigger: vague/ambiguous requests.
- `classify-change` — choose minimum sufficient rigor/depth by risk and impact. Trigger: uncertainty about required rigor/spec/governance.
- `slice-vertically` — decompose work into minimal complete outcomes. Trigger: planning implementation slices.
- `verify-evidence` — validate claims using sufficient/current evidence. Trigger: need to prove a result beyond assertion.
- `verify-completion` — decide whether work can legitimately be COMPLETE. Trigger: completion decision point.
- `diagnose-defect` — find first broken contract and drive smallest sound fix. Trigger: failed validation/test/behavior.
- `human-boundary` — decide if autonomous continuation is allowed. Trigger: consequential authority decision.
- `checkpoint-work` — preserve coherent validated progress safely. Trigger: save bounded progress before continuing/interrupting.
- `handoff-context` — transfer truthful resumable state across sessions/machines. Trigger: context/session/harness interruption.
- `assess-project` — build evidence-grounded understanding of an existing project. Trigger: start in unfamiliar existing repository.
- `adopt-oaem` — introduce OAEM incrementally with existing process reuse. Trigger: improve process without full migration.
- `reorganize-existing-project` — simplify messy repositories safely via vertical cleanup slices. Trigger: structural confusion/drift.
- `audit-documentation` — reduce doc complexity with authority/duplication/staleness analysis. Trigger: too many/contradictory docs.
- `oaem-help` — route users/agents to minimum sufficient OAEM flow. Trigger: uncertainty about which skill/path to use.
- `retrospective` — convert execution experience into evidence-grounded learning actions. Trigger: meaningful success/failure/friction learning event.
