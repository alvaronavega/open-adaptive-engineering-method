# Inspirations and Acknowledgments

## Purpose of this document

This document clarifies key inspirations behind OAEM and defines boundaries around attribution.

OAEM acknowledges valuable ideas from existing public work while maintaining its own independent methodology identity.

## Acknowledged inspirations

### GitHub Spec Kit

OAEM was inspired in part by principles demonstrated in GitHub Spec Kit, including:
- explicit engineering intent;
- structured planning;
- traceable artifacts;
- quality-oriented gating behavior;
- portability of structured workflows across different agent contexts.

These patterns helped validate that explicit structure can improve consistency in AI-assisted engineering.

### Skills for Real Engineers (Matt Pocock)

OAEM was also inspired in part by Skills for Real Engineers, including:
- small composable Skills;
- practical engineering workflows;
- vertical slicing habits;
- test-oriented and diagnostic execution behavior;
- adaptive application of process to task context.

These patterns helped reinforce that reusable micro-workflows can improve reliability and maintainability.

## What OAEM adds in response to practical gaps

OAEM emerged from long-running practical usage where additional method governance was needed, especially around:
- adaptive documentation depth;
- deterministic completion evidence;
- explicit completion contracts;
- human boundary clarity;
- cross-machine reproducibility;
- multi-agent and multi-harness isolation;
- checkpoint policy for long autonomous runs.

OAEM tries to combine composability with governance, rather than choosing one over the other.

## Important clarifications

OAEM is:
- **not a fork** of GitHub Spec Kit;
- **not a fork** of Skills for Real Engineers;
- **not endorsed** by those projects or their authors;
- **not a replacement claim** that those approaches are wrong.

OAEM recognizes both as important inspirations and extends methodology concerns required for its target operating context.

## Author-originated prior work

The repository `alvaronavega/documentacoes` is treated in OAEM as:
- **author-originated prior work**, not third-party inspiration.

It may inform conventions and discipline patterns where applicable, but it is not listed as third-party source attribution.

## Acknowledgment text (English canonical)

OAEM was inspired in part by GitHub Spec Kit and Matt Pocock’s Skills for Real Engineers.

GitHub Spec Kit highlighted the value of explicit intent, structured planning, traceable artifacts, and portable quality-oriented workflow framing.

Skills for Real Engineers highlighted the value of small adaptable composable Skills, vertical work slicing, practical diagnostics, and test-oriented engineering routines.

OAEM is not a fork or replacement for either project, and it is not endorsed by them.  
It emerged from practical long-running experience applying specification-driven and skill-driven approaches across multi-agent, multi-harness engineering contexts where additional governance and evidence contracts were needed.
